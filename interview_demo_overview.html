ESP32-S3 视觉交互终端项目

面向面试演示的项目梳理：摄像头采集、LCD/LVGL 本地交互、HTTP 图传、Wi-Fi 配网、拍照上传、AI 图像分析与本地目标检测。

工程目录：F:\ESP32project\esp_http_stream 平台：ESP32-S3 + ESP-IDF 显示：320x240 LCD + LVGL 摄像头：DVP / RGB565 / QVGA 检测：人脸 / 行人

一句话介绍

这是一个基于 ESP32-S3 的嵌入式视觉交互原型：设备端完成摄像头采集和本地屏幕预览，通过触摸 UI 触发拍照、上传和 AI 分析，同时保留 HTTP MJPEG 视频流、mDNS 发现、Wi-Fi 配网和本地行人/人脸检测能力。

面试时可以把它讲成“从硬件采集到网络服务再到 AI 识别的完整链路”，亮点是你不只做了单点功能，而是把摄像头、显示、触摸、联网、云端接口和端侧检测整合在一个 ESP-IDF 工程里。

注意：main/main.c 当前真正执行的代码主要是 NVS 初始化、写入编译期 Wi-Fi 账号、以 STA 模式联网。LCD、LVGL、触摸、摄像头、检测、mDNS 和 HTTP 服务初始化链路目前保留在一个大注释块中。

依赖与硬件配置

ESP-IDF 组件依赖

  • espressif/mdns：局域网服务发现。
  • espressif/esp32-camera：摄像头采集。
  • lvgl/lvgl：本地图形界面。
  • espressif/esp_lcd_touch_ft5x06：触摸屏。
  • espressif/esp-dl：端侧模型推理基础。
  • human_face_detect / pedestrian_detect：人脸与行人检测。

关键硬件参数

  • 主控：ESP32-S3。
  • 摄像头：DVP，RGB565，QVGA 320x240，XCLK 24 MHz。
  • 显示：SPI LCD，ST7789 驱动，RGB565。
  • 触摸：FT5x06 系列 I2C 触摸芯片。
  • 扩展 IO：PCA9557，控制 LCD CS、DVP PWDN 等信号。
  • 内存：摄像头帧和 canvas 主要使用 PSRAM，LCD DMA 使用内部 RAM。

面试讲解重点

可以重点展开的技术点

  • ESP-IDF 组件化：main、BSP、human_detect 分层。
  • FreeRTOS 任务拆分：UI、摄像头采集、LCD 刷新、拍照上传分开跑。
  • 内存取舍：PSRAM 放大缓冲，内部 DMA 内存用于 LCD SPI 传输。
  • HTTP MJPEG：用 multipart boundary 连续推 JPEG 帧。
  • 端云协同：ESP32 负责采集和上传，外部服务负责大模型图像理解。
  • 端侧 AI：使用 ESP-DL 相关组件做行人/人脸检测。

可以主动说明的工程思考

  • 把硬件驱动放进 BSP，后续换屏或换摄像头时影响范围更小。
  • 网络接口保留旧函数兼容层，说明你考虑过重构成本。
  • 上传和分析采用独立任务，避免 UI 卡死。
  • HTTP 响应缓冲按请求独立分配，降低并发请求互相污染风险。
  • 检测框直接画到 framebuffer，减少额外 UI 对象开销。

推荐 2 分钟口述稿

“这个项目是我基于 ESP32-S3 做的一个视觉交互终端。最底层我写了 BSP，负责 I2C、PCA9557、LCD、触摸和摄像头初始化；中间层是 Wi-Fi、HTTP、mDNS 和配网服务；上层是 LVGL 本地 UI，用户可以在屏幕上预览摄像头画面、拍照上传、触发 AI 分析，也可以打开本地检测，在画面上叠加人脸或行人检测框。”

“我比较关注嵌入式里的资源约束，所以摄像头帧、canvas 这类大内存放 PSRAM，LCD DMA 传输用内部 RAM 分块；网络上传和 AI 分析放到单独任务里，避免阻塞 UI。这个工程的价值在于它打通了采集、显示、传输、识别和交互的完整链路，不只是单独驱动一个外设。”
